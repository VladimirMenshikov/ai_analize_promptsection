# Prompt Optimization Project

Проект для систематического анализа ошибок классификации и итеративной оптимизации промпта на основе накопленной статистики.

---

## Как это работает

Рабочий цикл состоит из шести шагов, которые выполняются последовательно:

**Шаг 1 — Саммаризация ошибок.** Claude проверяет наличие файла саммаризации в `03_summary/`, покрывающего нужный диапазон дат. Если файла нет — создаёт его на основе файлов анализа из `02_analysis/periods/`. В  `02_analysis/periods/` файлы загружаются автоматически из проекта ежедневного анализа за период с предыдущего анализа. Саммаризация включает статистику ошибок, категории, частые пары «неверный → правильный отдел», системные паттерны и рекомендации по секциям промпта.

**Шаг 2 — Определение секций для оптимизации.** На основе саммаризации, полного промпта и дополнительных документов Claude определяет, какие секции требуют корректировки, и выводит их список для подтверждения.

**Шаг 3 — Загрузка секций.** Для каждой секции из списка Claude проверяет наличие файла в `01_input/sections/`. Если файл отсутствует — запрашивает его загрузку.

**Шаг 4 — Оптимизация.** Каждая секция переписывается по принципам необходимости и достаточности: убираются повторы и декоративные описания, добавляются конкретные маркеры и правила для граничных случаев, зафиксированных в саммаризации и дополнительных файлах.

**Шаг 5 — Сохранение результата.** Оптимизированные секции сохраняются в `04_output/optimized_sections/` с датой в имени файла. Claude выводит сводку: список обработанных секций и метрику сжатия (было / стало).

**Шаг 6 — Архивирование.** После подтверждения рабочие файлы переносятся в `archive/YYYY-MM-DD/`.

## Структура репозитория

```
01_input/
├── sections/           ← секции промпта для оптимизации (по одному файлу на секцию)
├── prompts/            ← текущий полный промпт
└── docs/               ← дополнительные условия, уточнения, запросы

02_analysis/
├── periods/            ← анализ ошибок по дням: analysis_YYYY-MM-DD.md
└── errors/             ← детализация ошибок по секциям

03_summary/             ← итоговая саммаризация: summary_errors_YYYY-MM-DD_to_MM-DD.md

04_output/
└── optimized_sections/ ← оптимизированные секции: [секция_ID]_YYYY-MM-DD.md

05_templates/           ← шаблоны файлов (хранятся в репозитории)

archive/
└── YYYY-MM-DD/         ← архив рабочих файлов по датам
```

> Репозиторий хранит только структуру каталогов и содержимое `05_templates/`. Рабочие файлы не коммитятся.

## Быстрый старт

Открой проект в Claude и используй одну из команд:

```
# Запустить полный цикл оптимизации
Запусти оптимизацию промпта

# Только создать саммаризацию по накопленным анализам
Создай саммаризацию по файлам в 02_analysis/periods/

# Узнать, какие секции требуют оптимизации
Какие секции нужно оптимизировать?

# Оптимизировать конкретную секцию
Оптимизируй секцию dept_returns

# Перенести файлы в архив
Перенеси файлы в архив
```

## Именование файлов

| Тип файла | Шаблон | Пример |
|---|---|---|
| Анализ за день | `analysis_YYYY-MM-DD.md` | `analysis_2026-05-25.md` |
| Саммаризация | `summary_errors_YYYY-MM-DD_to_MM-DD.md` | `summary_errors_2026-05-19_to_05-25.md` |
| Исходная секция | `[секция_ID].md` | `dept_returns.md` |
| Оптимизированная секция | `[секция_ID]_YYYY-MM-DD.md` | `dept_returns_2026-05-26.md` |

---

## Правила работы с файлами

- Файлы в `01_input/` и `02_analysis/` — **только чтение**, не изменяются в процессе оптимизации.
- Каждая секция сохраняется в **отдельный файл** — секции не объединяются.
- Существующие файлы саммаризации не удаляются — при новом диапазоне создаётся новый файл.
- Если полный промпт отсутствует в `01_input/prompts/` — работа останавливается на шаге определения секций.
